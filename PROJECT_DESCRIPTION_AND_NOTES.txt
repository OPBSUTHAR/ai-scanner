1. PROJECT OVERVIEW
----------------------------------------------------------------
AI Scanner is a monolithic Flask web application (one Docker container
serves both frontend and backend) that turns any phone, tablet or
desktop browser into an intelligent document scanner.

User flow: Upload / Camera Capture -> Edge Detection & Perspective
Correction -> Enhancement (shadow removal, contrast, sharpening) -> OCR
(Tesseract / Cloud Vision / EasyOCR) -> Classification (invoice,
receipt, ID, contract) -> Auto-naming -> Storage -> Search & Vault ->
Cloud Sync -> AI Assistant.

The app works on any device via browser. No separate frontend deployment
is needed. Camera live-view works over HTTPS; over HTTP it auto-falls
back to the native OS camera app.

This project was completed as part of the WebEnoid Internship and was
solely developed and implemented by Om Prakash Suthar (WebEnoid Intern).
All code, design, tests, docs and deployment were authored by me.

----------------------------------------------------------------
2. OBJECTIVE
----------------------------------------------------------------
To build a production-ready, AI-assisted scanner that:
- Captures documents accurately from phone cameras
- Enhances and extracts text reliably
- Organizes documents automatically
- Syncs to cloud and stays searchable
- Assists users with local/free AI that never hallucinates vault data

3. TECH STACK
----------------------------------------------------------------
Backend: Python 3.11/3.13, Flask, Gunicorn
Image Processing: OpenCV, scikit-image, SciPy, Pillow, NumPy
OCR: Tesseract OCR 5.5, Google Cloud Vision, EasyOCR (PyTorch CPU-only)
AI Assistant: Ollama (llama3.2/phi3/gemma2) -> Groq Cloud (llama-3.3-70b)
             -> Transformers (google/flan-t5-small) -> Built-in helper

Storage: LocalStorage (metadata JSON), ReportLab, img2pdf
Cloud Sync: Google Drive API, Dropbox API, OneDrive (MSAL/Graph API)
Security: Fernet encryption for API keys, path-traversal protection
Frontend: HTML, CSS (Classic Archive theme), JavaScript (no framework)
Deploy: Docker (python:3.11-slim-trixie + Tesseract + libzbar0), Gunicorn,
        Render (free), Railway, Coolify/VPS | Root Directory = ai_scanner
Testing: pytest (73 tests), Flask test_client, Docker E2E

----------------------------------------------------------------
4. KEY FEATURES
----------------------------------------------------------------
A) Capture & Scan
   - Upload (drag-drop) and Camera (getUserMedia live view)
   - Universal fallback: HTTP/old browser -> native camera input
   - Device selector for USB/external cameras

B) Image Intelligence
   - Auto edge detection + perspective correction
   - Dewarp for curved pages, shadow removal, auto-contrast (CLAHE)
   - Multi-shot fusion (ECC align + median) for glare reduction
   - Effects: grayscale, binarize (Otsu), sharpen, invert
   - Quality assessment: blur (Laplacian variance), brightness, lighting

C) OCR & Classification
   - Tesseract (auto-detected on Windows/Linux/Mac) + Cloud Vision + EasyOCR
   - Document type: invoice/receipt/ID/contract/unknown
   - Extraction: amounts, dates, due dates, invoice numbers
   - QR/barcode detection

D) Storage & Vault
   - Auto-naming: e.g., Invoice_AcmeCorp_March15_$234.50.png
   - Saves to data/documents/{type}/{filename} + metadata JSON
   - Vault: grid/list, filters, preview modal, rename, delete
   - Search: full-text across OCR text
   - Batch: multi-file upload -> instant processing -> preview -> Done & Save
   - Office docs (docx/xlsx/pptx) -> PDF conversion, PDF merge (reportlab)
   - Dashboard: stats (total, size, types), recent scans, activity feed

E) Cloud Sync
   - Google Drive, Dropbox, OneDrive OAuth (per-user tokens)
   - Multi-user isolation: tokens per user (tokens/<user>.<provider>.json)
   - Real-time usage stats, folder view

F) Authentication & UX
   - Login/Register + Guest (GUEST-XXXX unique ID), session cookies
   - Bluetooth Camera QR pairing (/bt/cam/<token>), HTTPS support
   - Classic Archive theme: cream/parchment, burgundy/gold, leather-book
     sidebar, Playfair/Lora/JetBrains Mono fonts, Lucide icons, boot splash

G) AI Assistant (Free, Local, No API Keys Required)
   - Summarize any scan, ask questions, extract key facts
   - Grounded in real vault: injects live facts (counts, categories,
     recent filenames) so it never invents files; vault questions answered
     deterministically
   - Available in: Dashboard (Archive Overview), Scanner (Summary + Tips),
     Vault (per-doc Summary/KEY FACTS + multi-doc Briefing), Settings
     (engine status), dedicated AI Assistant view
   - Chain: Ollama -> Groq (free) -> Transformers -> Built-in (always)

5. ARCHITECTURE
----------------------------------------------------------------
Browser --HTTPS--> Flask + Gunicorn (ONE container, ai_scanner/)
                    |-- templates/ + static/css + static/js (served by Flask)
                    |-- /scan, /batch, /history, /api/ai/*, /api/keys etc.
                    |-- LocalStorage at /app/data (Render) or ai_scanner/data
No Vercel/Netlify split. Dockerfile builds system deps (tesseract, zbar).

8. DEPLOYMENT
----------------------------------------------------------------
Live: https://ai-scanner-fnjh.onrender.com/ (Render free, Oregon, Docker,
Root Directory ai_scanner, auto-deploy on git push main)

Steps: Render Dashboard -> New Web Service -> repo OPBSUTHAR/ai-scanner ->
Root Directory ai_scanner, Runtime Docker, env APP_ENV=production
APP_DEBUG=False DATA_DIR=/app/data GUNICORN_WORKERS=1 DISABLE_EASYOCR=1
AI_DISABLE_TRANSFORMERS=1 MAX_SCAN_DIM=2000 GROQ_API_KEY (optional, enables
cloud AI) -> Create -> 5-10 min build -> verify GET / + scan + AI.

Alternatives documented in DEPLOYMENT_GUIDE.md: Railway (~$5/mo),
Coolify on VPS (~$4.5/mo, persistent /app/data).

Limits (free tier): 512MB RAM, sleeps after 15 min idle (30-60s wake),
ephemeral disk (scans lost on redeploy — use Drive/Dropbox sync).

9. CHALLENGES & SOLUTIONS
----------------------------------------------------------------
- Duplicate data/ folder -> resolved via file-relative base_dir
- Camera over HTTP blocked -> fallback to native input capture
- PKCE verifier lost / redirect_uri_mismatch -> stateless + exact callback
- Token loss on restart -> _load_token + per-user files
- Path traversal -> _resolve_within check
- Fernet race on 2 workers -> atomic os.replace + retry
- AI hallucinated files -> inject live vault facts + deterministic branch
- *.json gitignore hid railway.json -> !railway.json exception
- GitHub Add a README banner -> added root README.md entrypoint
